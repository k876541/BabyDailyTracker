# 當日提醒篩選與寶寶資料重設設計

## 目的

建立今天開始的餵藥療程時，略過今天已經過去的固定時段，仍排入今天其餘時段與後續日期。新增設定頁，讓目前只支援一位寶寶的 App 能安全清除所有本機資料並重新進入首次設定流程。

## 採用方案

- 提醒排程：保留原始每日固定時段設定，只在產生實際 occurrence 時過濾 `<= now` 的時間。若過濾後至少還有一筆就建立療程；完全沒有未來時段才顯示「提醒時間必須晚於現在」。
- 資料移除：採完整重設，不只刪除姓名與生日，避免新寶寶看到上一位寶寶的紀錄。
- 畫面：在主分頁新增「設定」頁。按下「移除寶寶資料」後依序顯示兩個確認對話框；第二次確認使用破壞性按鈕並清楚列出不可復原。

## 曾考慮的方案

- 要求使用者手動刪掉今天已過時段：實作簡單，但每日時段本來就是整段療程設定，會迫使使用者為第一天修改規則，因此不採用。
- 只刪除寶寶個人資料：會留下飲食、睡眠、排便、成長與餵藥資料，下一位寶寶可能看到舊資料，因此不採用。

## 資料與流程

1. Coordinator 依現在時間過濾展開後的 occurrence；建立與編輯共用同一規則。
2. 設定頁的 ViewModel 先取得所有尚未完成的餵藥 occurrence ID。
3. Repository 清除 `BabyProfile`、`GrowthRecord`、`MealRecord`、`SleepRecord`、`DiaperRecord` 與 `MedicationReminderPlan`；療程子模型依 cascade 一併清除。
4. 資料成功清除後取消對應的待發本機通知，並通知 App root 切回 `needsBabyProfile`。
5. 若資料清除失敗，留在設定頁並顯示錯誤，不切換 onboarding。

## 驗證與安全性

- 今天 12:17 設定 09:00、13:00、17:00 時，只建立 13:00、17:00 與後續日期的 occurrence。
- 所有時間都已過且沒有後續日期時仍拒絕儲存。
- 編輯療程也不重新建立已過時段。
- 第一次確認不改動資料；只有第二次確認才執行重設。
- 重設成功後所有本機紀錄消失、待發餵藥通知取消並顯示 onboarding。
- 重設失敗時保留畫面與資料，提供可理解的錯誤訊息。

## 不包含

- 多寶寶切換或封存。
- 雲端刪除、帳號刪除或跨裝置同步。
- 復原已清除資料。
